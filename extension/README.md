# 微博 / X 原生定时助手 · Chrome 扩展

这是不依赖 OpenCLI、Codex 或付费 API 的 Manifest V3 扩展。它复用当前 Chrome 已登录的网页，生成多平台时间表、填写原生定时编辑器、记录提交过程。**初版采用逐条操作和人工核对，不是无人值守的全自动批量发布器。**

只有平台真正保存帖子后，关机发送才由平台负责。助手没有到点发送的后台进程。

## 安装

1. 下载仓库，或解压发布的 `social-native-scheduler-chrome.zip`。
2. 打开 `chrome://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的 `extension` 文件夹（ZIP 解压后为 `social-native-scheduler-chrome`）。
4. 点击扩展图标，助手会打开独立网页。保持助手页打开，直到这一批存好；误关后可重新打开，记录保留。

## 使用

每条文案用单独一行 `---` 分隔；正文可有换行。开始时间固定北京时间，两个平台使用相同正文和时间。不要把 `---` 当正文中的单独一行。

生成计划 → 打开平台并确认账号 → 刷新网页列表 → 选择平台网页或微博编辑器所在框架 → 输入账号名 → 填写原生编辑器 → 在平台检查正文、完整日期时间及时区 → 回助手保存 → 在平台待发布列表检查正文和时间 → 勾选并记录已核验。然后选择下一条。

微博创作者中心可能通过 iframe 嵌入编辑器。打开“发布定时微博”后刷新助手网页列表，选择标为“有编辑器”的框架。控件无法定位时会停止；可手动设置平台控件，再检查或重新填写。X 目前支持页面上的英文日期标签及部分中文标签；未知语言或非北京时间会停止。

“结果待核对”表示可能已保存。断线或报错后先查待发布、已发布列表，不能直接重试。确认平台没有保存后才能重置。更换本地计划、重置或卸载扩展都**不会**取消平台帖子，取消需在平台操作。

## 支持范围和验证边界

- 文字帖；不处理图片、视频、长文、验证码或会员购买。
- X 与微博账号、原生定时能力、额度及正文限制由平台决定。账号名由用户查看网页后填写，扩展不自动验证身份。
- DOM 定位来自 2026-10-04 的网页操作经验，页面升级可能需要适配。
- 完成状态表示人工在平台核验；扩展没有自动读取服务器队列的能力。
- 开发验证包含时间计算、跨日同步、错误输入和中断后禁止直接重试；没有用新的真实帖子验证扩展端到端发布。安装后先用一条较远时间的帖子检查全过程，必要时在平台取消。
- 没有 Chrome Web Store 发布；当前交付为可加载的源码 ZIP。

## 隐私与权限

`storage` 保存当前任务的文案、时间、手填账号名和状态；`scripting` 在用户选择的平台页/框架操作编辑器。网站访问只限 `x.com` 和 `weibo.com` 及微博子域，以覆盖嵌入的创作者页面。不访问 Cookie API，不收集密码或令牌，不发送数据到第三方，没有统计追踪或远程代码。

导出记录可能含个人文案和账号名，请自行保管，不要上传公共仓库。清除扩展数据或卸载扩展可移除本地任务清单。

## 开发

无需依赖安装或构建，直接加载 `extension/`。Node 22+：

```
node --test extension/tests/*.test.mjs
```

权限及注入实现参考 [Chrome 官方权限说明](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions) 和 [chrome.scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)。
